# Dev dependencies: Babel 8.1 via npm-check-updates

## Original prompt

> rode `npx npm-check-updates -u` e teste
>
> (later) podemos atualizar o fork também, sem problema

## What was implemented

`npx npm-check-updates -u` raised every Babel package to the latest 8.x:

| Package | Before | After |
| --- | --- | --- |
| `@babel/cli` | ^8.0.1 | ^8.1.0 |
| `@babel/core` | ^8.0.1 | ^8.1.0 |
| `@babel/plugin-transform-class-properties` | ^8.0.0 | ^8.0.1 |
| `@babel/plugin-transform-export-namespace-from` | ^8.0.1 | ^8.1.0 |
| `@babel/plugin-transform-runtime` | ^8.0.1 | ^8.0.6 |
| `@babel/preset-env` | ^8.0.2 | ^8.0.7 |
| `@arijs/babel-plugin-transform-modules-umd` | ^0.1.5 | ^0.1.6 |

`@babel/core` 8.1.0 broke the build: `@arijs/babel-plugin-transform-modules-umd`
0.1.5 asserted exactly `"8.0.1"`. The fork's build had replaced
`REQUIRED_VERSION("^7.0.0-0 || ^8.0.0")` with the monorepo's exact core version,
because it ran without `IS_PUBLISH`. Fixed in the fork (`arijs/babel`, branch
`modules-umd-imports-get-module-id`, commit `dd7a3f3`) by asserting the literal
range, and published as 0.1.6. `@arijs/babel-helper-module-transforms` did not
change (its rebuilt `lib/` is identical to 0.1.4).

`npm-check-updates` also proposed `@babel/runtime` ^8.1.0. It stays at ^8.0.0:
it is the package's only runtime dependency, and the compiled `lib/` is the
same, so raising the floor would only force consumers to upgrade for nothing
(fresh installs resolve 8.1.0 anyway).

## Before / after

- Before: Babel 8.0.x, 290 packages in the tree.
- After: Babel 8.1.0, 158 packages (Babel 8.1 dropped dependencies),
  `npm audit` 0.

## How it was tested

- With `@babel/core` 8.1.0 and the UMD plugin 0.1.5: build fails
  (`Requires Babel "8.0.1", but was loaded with "8.1.0"`).
- With `@babel/core` held at 8.0.1 and the rest updated: green, to isolate the
  cause.
- Fork: 130 plugin/helper tests pass; the rebuilt plugin differs from 0.1.5
  only in the `assertVersion` range (and the `@arijs` helper import, renamed
  when packaging, as before).
- The published 0.1.6 tarball has the same shasum as the one tested locally.
- `npm ci` from the new lock, `npm test`: all green. `lib/` is byte-for-byte
  identical to the previous build.
- `npm ci` with npm 10.9.8 (CI on Node 22): installs cleanly.

## Tests created / changed

None in this repo: no source change, and the existing suite covers the build
output. In the fork, the existing plugin fixtures cover the change.
